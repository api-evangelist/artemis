# Artemis — NASA Open APIs

> NASA's Artemis program is the United States' return-to-the-Moon effort: the Space Launch System,
> the Orion spacecraft, the Lunar Gateway station and commercial landers. The programmatic surface
> API Evangelist tracks under this record is NASA's public developer platform at api.nasa.gov —
> sixteen catalogued public APIs covering imagery, near-earth objects, space weather, Earth
> observation, planetary map tiles and technology transfer — plus the OGC map services that serve
> lunar and planetary imagery.

Provenance: generated 2026-09-04 by the API Evangelist enrichment pipeline from this repository's
artifacts and NASA's own published catalog at https://api.nasa.gov/assets/json/apis.json. NASA does
not publish an llms.txt; probed /llms.txt on api.nasa.gov, www.nasa.gov, technology.nasa.gov and
images-api.nasa.gov, all 404 on 2026-09-04.

## What you need to know before calling anything

- Base URL: https://api.nasa.gov (the NASA Image and Video Library is on https://images-api.nasa.gov;
  TechPort is on https://techport.nasa.gov/api).
- Auth: one `api_key` **query parameter**. No header form is documented. `DEMO_KEY` works with no
  signup at 30 requests/hour and 50/day per IP; a free registered key raises that to 1,000/hour.
- Everything is read-only. Every documented operation is a GET over public data. There is no write,
  so no idempotency and no reversal to worry about.
- Rate-limit signal: `X-RateLimit-Limit` and `X-RateLimit-Remaining` on every response. There is no
  reset header and no `Retry-After`. Exhaustion is HTTP 429 `OVER_RATE_LIMIT`, cleared on a rolling
  hour.
- Errors come in two shapes on the same host. Gateway failures (auth, rate limit, routing) are
  `{"error":{"code":"...","message":"..."}}`; upstream service validation failures are
  `{"code":400,"msg":"...","service_version":"v1"}`. Branch on the HTTP status and `error.code`,
  never on message text.
- There is no status page, no changelog, no deprecation policy and no SLA. Assume no notice before a
  breaking change.
- There is no official SDK in any language and no MCP server.

## Operations

- `getApod` GET /planetary/apod — Astronomy Picture of the Day; `date`, or `start_date`+`end_date`,
  or `count` for random. Coverage starts 1995-06-16.
- `getNeoFeed` GET /neo/rest/v1/feed — near-earth objects by close-approach window; `start_date`,
  `end_date`, maximum 7 days apart.
- `lookupNeo` GET /neo/rest/v1/neo/{asteroid_id} — one asteroid by JPL SPK-ID (example: 3542519).
- `browseNeo` GET /neo/rest/v1/neo/browse — page the whole dataset; `page` and `size`, response
  carries `page.total_elements` / `page.total_pages`.
- `getDonkiNotifications` GET /DONKI/notifications — solar flares, geomagnetic storms and radiation
  events. The mission-relevant feed for crew safety and launch windows.
- `getEpicNatural` GET /EPIC/api/natural — latest full-disc Earth image metadata.
- `getEpicNaturalByDate` GET /EPIC/api/natural/date/{date} — same, for a specific date.
- `searchImages` GET https://images-api.nasa.gov/search?q= — NASA Image and Video Library; `page`
  and `page_size`, response carries `collection.metadata.total_hits` and prev/next links.

## Also worth knowing

- NASA's catalog lists sixteen APIs; this record holds contracts for five plus TechPort. The others
  (EONET, Exoplanet Archive, GIBS, InSight, Open Science Data Repository, Satellite Situation Center,
  SSD/CNEOS, TechTransfer, TLE) are documented on api.nasa.gov but have no machine-readable contract.
- The TLE API in NASA's catalog points at a third-party host (tle.ivanstanojevic.me), not a NASA one.
- api.nasa.gov keys work across other US federal agencies on the same api.data.gov gateway.
